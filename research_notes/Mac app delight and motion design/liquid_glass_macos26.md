# Liquid Glass on macOS 26 (Tahoe) for a custom-branded third-party SwiftUI Mac app

Scope: macOS focus. Sources are Apple documentation (fetched as the `.md` variants of developer.apple.com pages, dated "Copyright 2026 Apple"), WWDC25 session transcripts, and developer write-ups from 2025–2026. Where a source is iOS-centric, that is flagged. Note: Apple's HIG "Liquid Glass" page itself could not be fetched (JavaScript-only render); its content is covered via the WWDC25 "Meet Liquid Glass" transcript, the "Adopting Liquid Glass" technology overview, and a mirrored copy of the HIG Materials page.

## Key question 1: What does Liquid Glass look like by default on macOS 26, and what are the exact SwiftUI APIs, their minimum OS, and clean `#available` branching?

### Takeaway
Every Liquid Glass SwiftUI API (`glassEffect`, `Glass`, `GlassEffectContainer`, `glassEffectID`, `glassEffectUnion`, `buttonStyle(.glass/.glassProminent)`, `ToolbarSpacer`, `sharedBackgroundVisibility`, `backgroundExtensionEffect`, `searchToolbarBehavior`, `scrollEdgeEffectStyle`) is macOS 26.0+ and appears automatically only when the app is built with the Xcode 26 SDK; on macOS 14/15 none of it exists, so the app needs `if #available(macOS 26, *)` branches (or a small wrapper modifier) for every custom use, while standard toolbars, sidebars, sheets, menus and buttons pick up glass with no code at all.

### Cited Findings

Default appearance on macOS 26 (system-provided, no code):
- "If your app uses standard components from SwiftUI, UIKit, or AppKit, your interface picks up the latest look and feel on the latest platform releases ... In Xcode, build your app with the latest SDKs, and run it on the latest platform releases to see the changes." — [Apple: Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)
- "standard components like bars, sheets, popovers, and controls automatically adopt this material. System frameworks also dynamically adapt these components in response to factors like element overlap and focus state." — [Apple: Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)
- Toolbars: "toolbar items are placed on a Liquid Glass surface that floats above your app's content." Items group automatically into shared-background pills. — [WWDC25 323 "Build a SwiftUI app with the new design" transcript](https://nonstrict.eu/wwdcindex/wwdc2025/323/)
- Sidebars: `NavigationSplitView` sidebars "now have a Liquid Glass sidebar that floats above your content." Inspectors get "more subtle layering." — [WWDC25 323 transcript](https://nonstrict.eu/wwdcindex/wwdc2025/323/)
- Search on Mac: toolbar search "appears in the top-trailing position of the toolbar." Applying `searchable` to the `NavigationSplitView` makes search span the whole split view. — [WWDC25 323 transcript](https://nonstrict.eu/wwdcindex/wwdc2025/323/)
- Controls: bordered buttons default to a capsule; "Mini, small, and medium size controls on macOS retain a rounded-rectangle shape." "Most controls on macOS are slightly taller." Menu icons are "now used on macOS too," on the leading edge. — [WWDC25 323 transcript](https://nonstrict.eu/wwdcindex/wwdc2025/323/)
- Controls: "For controls like sliders and toggles, the knob transforms into Liquid Glass during interaction, and buttons fluidly morph into menus and popovers ... Controls also feature an option for an extra-large size." — [Apple: Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)
- Menus: "Menus have a refreshed look across platforms. They adopt Liquid Glass, and menu items for common actions use icons." — [Apple: Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)
- Windows and sheets: "Windows adopt rounder corners to fit controls and navigation elements." "Sheets feature an increased corner radius." Action sheets/dialogs originate from the control that triggered them. — [Apple: Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass); dialogs "automatically morph out of the buttons that present them" — [WWDC25 323 transcript](https://nonstrict.eu/wwdcindex/wwdc2025/323/)
- Lists/forms: "lists, tables, and forms have a larger row height and padding. Sections have an increased corner radius"; section headers use title-style capitalization instead of all caps. — [Apple: Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)
- Mac-specific material behavior: "Glass controls nest perfectly into the rounded corners of windows, maintaining concentricity." Sidebars: "Light from colorful content nearby can subtly spill onto its surface." Large elements (menus, sidebars) "don't flip from light to dark," small elements (bars) do. "when a window loses focus on the Mac or iPad, Liquid Glass shifts its appearance and visually recedes." Menus presented from toolbar buttons "simulate a thicker, more substantial material." — [WWDC25 219 "Meet Liquid Glass" transcript](https://developer.apple.com/videos/play/wwdc2025/219)
- Press description of first-party Mac apps: Safari has a "now transparent address bar"; Music, Notes, and Preview "feature floating toolbars and sidebars and heavily rounded corners"; rounder window corners "apply only to redesigned apps, while other apps retain the older look." — [MacStories: macOS Tahoe overview](https://www.macstories.net/news/macos-tahoe-the-macstories-overview/)
- Reviewer (beta-era) critique: macOS toolbars show "not-so-transparent gray-shaded buttons and navigation bars" with dated shadows; glass parts "feel cobbled together with the previous design language"; Liquid Glass "looks better on darker backgrounds." — [MacRumors macOS Tahoe review (Aug 2025)](https://www.macrumors.com/2025/08/01/macos-tahoe-review)
- macOS 26.1 added a Liquid Glass appearance setting with two options: "Clear is more transparent, revealing the content beneath." and "Tinted increases opacity and adds more contrast." Reduce Transparency or Increase Contrast overrides it and "disables all Liquid Glass effects." — [Eclectic Light Co., Nov 2025](https://eclecticlight.co/2025/11/05/appearance-revisited-get-tahoe-26-1-looking-in-better-shape/)

API availability (all from Apple's symbol pages, availability block):
- `GlassEffectContainer` — iOS/iPadOS/macCatalyst/macOS/tvOS/watchOS 26.0+. "A view that combines multiple Liquid Glass shapes into a single shape that can morph individual shapes into one another." Spacing: "The higher the spacing, the sooner blending begins as the shapes approach each other." — [Apple: GlassEffectContainer](https://developer.apple.com/documentation/swiftui/glasseffectcontainer)
- `Glass` struct — macOS 26.0+; `.regular`, `.clear`, `.identity` ("your content remains unaffected as if no glass effect was applied"), `.tint(Color?)`, `.interactive(Bool)`. — [Apple: Glass](https://developer.apple.com/documentation/swiftui/glass)
- `glassEffect(_:in:)` defaults: "By default, the modifier uses the regular variant of Glass and applies the given effect within a Capsule shape." Examples: `.glassEffect()`, `.glassEffect(in: .rect(cornerRadius: 16.0))`, `.glassEffect(.regular.tint(.orange).interactive())`. "Apply the glassEffect(_:in:) modifier after other modifiers that affect the appearance of the view." — [Apple: Applying Liquid Glass to custom views](https://developer.apple.com/documentation/swiftui/applying-liquid-glass-to-custom-views)
- `glassEffectID(_:in:)` + `@Namespace` coordinate morphing; `GlassEffectTransition` has `.matchedGeometry` (default when within container spacing) and `.materialize` (for effects farther apart). "The glassEffectID(_:in:) and glassEffectTransition(_:) modifiers only affect their content during view hierarchy transitions or animations." — [Apple: Applying Liquid Glass to custom views](https://developer.apple.com/documentation/swiftui/applying-liquid-glass-to-custom-views)
- `glassEffectUnion(id:namespace:)` merges multiple views into one glass shape at rest "especially useful when creating views dynamically, or with views that live outside of a layout container." — [Apple: Applying Liquid Glass to custom views](https://developer.apple.com/documentation/swiftui/applying-liquid-glass-to-custom-views)
- Button styles: SwiftUI `PrimitiveButtonStyle.glass`, `.glassProminent`, `.glass(_:)`; AppKit `NSButton.BezelStyle.glass`; AppKit custom glass is `NSGlassEffectView`, UIKit `UIGlassEffect`. — [Apple: Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)
- `glassProminent` "uses the accent color or the user's chosen theme color" by default; both `.glass` and `.glassProminent` accept a tint. — [troz.net: SwiftUI for Mac 2025](https://troz.net/post/2025/swiftui-mac-2025/)
- `backgroundExtensionEffect()` — macOS 26.0+. "The view will be duplicated into mirrored copies which will be placed around the view on any edge with available safe area. Additionally, a blur effect will be applied on top." "Apply this modifier with discretion. This should often be used with only a single instance of background content." Note: "This modifier will clip the view." Example wraps a banner in the `detail:` column of `NavigationSplitView` with `.inspector`. — [Apple: backgroundExtensionEffect()](https://developer.apple.com/documentation/swiftui/view/backgroundextensioneffect())
- `ToolbarSpacer(.fixed)` / `ToolbarSpacer(.flexible)` — used in Apple's Landmarks sample (sample availability: iOS 26.0+, macOS 26.0+, Xcode 26.0+). — [Apple: Landmarks: Refining the system provided Liquid Glass effect in toolbars](https://developer.apple.com/documentation/swiftui/landmarks-refining-the-system-provided-glass-effect-in-toolbars)
- `sharedBackgroundVisibility(.hidden)`: "Apply the sharedBackgroundVisibility modifier to separate an item into its own group without a background." `badge` on toolbar item content is supported. — [WWDC25 323 transcript](https://nonstrict.eu/wwdcindex/wwdc2025/323/)
- `searchToolbarBehavior(_:)` — macOS 26.0+ (all platforms 26). "Place this modifier after the searchable(...) modifier that renders search in the toolbar." The documented example (`.minimized`) is described for iPhone's bottom toolbar. — [Apple: searchToolbarBehavior(_:)](https://developer.apple.com/documentation/swiftui/view/searchtoolbarbehavior(_:))
- `tabBarMinimizeBehavior(_:)` — declared macOS 26.0+, but the documented behavior is "minimizes its tab bar when scrolling ... on iPhone." — [Apple: tabBarMinimizeBehavior(_:)](https://developer.apple.com/documentation/swiftui/view/tabbarminimizebehavior(_:)); the adoption guide frames it as "Choose whether to automatically minimize your tab bar in iOS." — [Apple: Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)
- `scrollEdgeEffectStyle(_:for:)` and `safeAreaBar(edge:alignment:spacing:content:)` register custom bars for the scroll edge effect. — [Apple: Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)
- Concentric shapes: `Shape.rect(corners:isUniform:)` and `ConcentricRectangle` for corners that nest into window corners. — [Apple: Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)
- `interactive()` is described as iOS-only in the WWDC transcript ("The interactive modifier is iOS-only, per the transcript"). — [WWDC25 323 transcript](https://nonstrict.eu/wwdcindex/wwdc2025/323/) (note: the API itself is declared on `Glass` for all 26 platforms per [Apple: Glass](https://developer.apple.com/documentation/swiftui/glass); the transcript statement is about where the pointer/touch reaction is meaningful)
- Toolbar container rules: "glass can not sample other glass" across containers, so group nearby glass in one `GlassEffectContainer`. — [WWDC25 323 transcript](https://nonstrict.eu/wwdcindex/wwdc2025/323/)

Availability-branching patterns from developer sources:
- Majid Jabrayilov shows the pattern of keeping a pre-26 label style with `@available(iOS, introduced: 18, obsoleted: 26, message: "Remove this property in iOS 26")` and an `if #available(iOS 26, *) { Label(configuration) } else { Label(configuration).labelStyle(.titleOnly) }` branch inside a custom `LabelStyle`. — [Swift with Majid: Glassifying toolbars in SwiftUI](https://swiftwithmajid.com/2025/07/01/glassifying-toolbars-in-swiftui/)
- Apple forum repro uses `if #available(macOS 26.1, *) { accessory.preferredScrollEdgeEffectStyle = .hard }` — note that some AppKit scroll-edge properties are 26.1+, not 26.0. — [Apple Developer Forums thread 827686](https://developer.apple.com/forums/thread/827686)
- Zipic (macOS 26 upgrade): `.windowStyle(.hiddenTitleBar)` left "a blank strip at the top of the window" on device (not in previews); fix was `.containerBackground(.clear, for: .window)`, which "requires macOS 15 or later, so older systems need conditional checks." — [fatbobman: Zipic development retrospective](https://fatbobman.com/en/posts/zipic-3-technical-details/)

### Inferences
- Because every glass API is 26.0+ and the app targets macOS 14/15, the cleanest structure is a handful of small `ViewModifier` wrappers (e.g., `GlassIfAvailable(shape:tint:)`, `GlassButtonIfAvailable`) whose `body` does `if #available(macOS 26, *) { content.glassEffect(...) } else { content.background(.regularMaterial, in: shape) }`, so call sites stay flat. Apple's `Glass.identity` exists precisely so a glass configuration can be "turned off" inside a 26-only branch without restructuring.
- Toolbar grouping (`ToolbarSpacer`) and `sharedBackgroundVisibility` cannot be used on 14/15 at all, so the `.toolbar { }` content block itself needs an `#available` split (ToolbarContent builders accept `if #available`), returning a flat set of `ToolbarItem`s for older systems.
- `tabBarMinimizeBehavior` is irrelevant for a Mac app; Apple's own wording ties it to iPhone.

### Gaps
- Apple's HIG "Liquid Glass" page and the "Toolbars"/"Windows" HIG pages could not be fetched (JavaScript-rendered, no `.md` variant); any HIG wording here comes from the technology-overview page and WWDC transcripts.
- No Apple document found that states a minimum-SDK rule for Liquid Glass other than "build with the latest SDKs"; Qt's blog confirms building with Xcode 16 keeps the old look (see Q3).
- The `.glass(_:)` button style variant's exact signature was not fetched.

## Key question 2: How should a hidden-title-bar, unified-toolbar window be laid out on macOS 26 so the toolbar reads as intentional (title, search, primary action grouping), and how should a custom-palette app coexist with glass chrome?

### Takeaway
Apple's guidance is that glass is only the floating navigation/control layer: keep the toolbar free of custom backgrounds, let the content layer (your warm, colorful cards) carry the brand color, group toolbar items by function with `ToolbarSpacer(.fixed)`, keep one primary action visually distinct (tint or `.confirmationAction`/`glassProminent`), and use the background extension effect so brand color spills under sidebars rather than leaving the glass floating over a blank strip — which is the usual cause of a "floating oddly" title or + button.

### Cited Findings

Content layer versus glass layer (the core rule):
- "You may be tempted to use Liquid Glass everywhere but it is best reserved for the navigation layer that floats above the content of your app." "Consider this tableview: making it Liquid Glass would make it compete with other elements and muddy the hierarchy. So keep it in the content layer instead." — [WWDC25 219 "Meet Liquid Glass"](https://developer.apple.com/videos/play/wwdc2025/219)
- "Liquid Glass belongs to the navigation and control layer. Keep it out of the content layer, and use standard materials for content-layer elements such as app backgrounds. The one exception is transient interactive elements like sliders and toggles." — [Apple HIG Materials (mirrored copy)](https://glama.ai/mcp/servers/@tmaasen/apple-dev-mcp/blob/b82f0efe2115dc4539c83a2374a714a84aeb350a/content/universal/materials.md)
- "Establish a clear navigation hierarchy ... Ensure that you clearly separate your content from navigation elements, like tab bars and sidebars, to establish a distinct functional layer above the content layer." — [Apple: Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)
- "always avoid glass on glass ... When placing elements on top of Liquid Glass, avoid applying the material to both layers. Instead, use fills, transparency, and vibrancy for the top elements." — [WWDC25 219](https://developer.apple.com/videos/play/wwdc2025/219)
- "Avoid overusing Liquid Glass effects. If you apply Liquid Glass effects to a custom control, do so sparingly ... Limit these effects to the most important functional elements in your app." — [Apple: Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)

Toolbars and custom backgrounds:
- "Reduce your use of custom backgrounds in controls and navigation elements. Any custom backgrounds and appearances you use in these elements might overlay or interfere with Liquid Glass or other effects that the system provides, such as the scroll edge effect ... Prefer to remove custom effects and let the system determine the background appearance" — explicitly listing SwiftUI `NavigationSplitView`, `WindowStyle.titleBar`, `toolbar(content:)`, and AppKit `NSToolbar`/`NSSplitView`. — [Apple: Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)
- Audit for "background colors behind sheets and toolbars that you can remove." Remove custom backgrounds or darkening behind bar items since "these will interfere with the effect." Use `scrollEdgeEffectStyle` to make the edge effect sharper on dense UIs. — [WWDC25 323 transcript](https://nonstrict.eu/wwdcindex/wwdc2025/323/)
- "Determine which toolbar items to group together. Group items that perform similar actions or affect the same part of the interface, and maintain consistent groupings and placement across platforms." Apple's incorrect/correct illustration: Undo, Redo, Markup, More all in one pill (incorrect) vs. Undo+Redo in one pill and Markup+More in another (correct), separated with `ToolbarSpacer(.fixed)`. — [Apple: Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)
- "For consistency, don't mix text and icons across items that share a background." "Provide an accessibility label for every icon." "If you see an empty toolbar item without any content, your app might be hiding the view in the toolbar item instead of the item itself" — hide the item with `ToolbarContent.hidden(_:)` / `NSToolbarItem.isHidden`. — [Apple: Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)
- Apple's Landmarks sample toolbar: `ToolbarSpacer(.flexible)` first (pushes everything trailing), then `ToolbarItem { ShareLink }`, `ToolbarSpacer(.fixed)`, `ToolbarItemGroup { favorite; collectionsMenu }`, `ToolbarSpacer(.fixed)`, `ToolbarItem { Button("Info", systemImage: "info") }`. — [Apple: Landmarks toolbars sample](https://developer.apple.com/documentation/swiftui/landmarks-refining-the-system-provided-glass-effect-in-toolbars)
- Placement implies styling: `.confirmationAction` placement applies the `glassProminent` style; the pattern `ToolbarItem(.cancellationAction)` / `ToolbarItemGroup(.primaryAction) { Draw; Erase }` / `ToolbarSpacer(.flexible)` / `ToolbarItem(.confirmationAction) { Save }` is shown. — [Swift with Majid: Glassifying toolbars](https://swiftwithmajid.com/2025/07/01/glassifying-toolbars-in-swiftui/)
- Toolbar tinting: "use this to convey meaning, like a call to action or next step, but not just for visual effect." Icons "use monochrome rendering in more places, including in toolbars." — [WWDC25 323 transcript](https://nonstrict.eu/wwdcindex/wwdc2025/323/)
- macOS quirk: with mixed placements, "on macOS, Action 1 sits in the top trailing position and the whole action group is centered in the navigation bar," whereas iOS pins Action 1 trailing and collapses the rest. There is "no customizable ToolbarItemGroup API" (you "cannot give a ToolbarItemGroup an id" inside `toolbar(id:content:)`); customizable and regular toolbars "overlap, but they are not interchangeable." — [Michael Tsai: SwiftUI Toolbars (Sep 2026)](https://mjtsai.com/blog/2026/09/08/swiftui-toolbars/)
- `ToolbarSpacer` grouping behaves differently by container: under `tabViewStyle(.sidebarAdaptable)` "items stayed grouped"; a standard tab style "produced separate groups." — [troz.net: SwiftUI for Mac 2025](https://troz.net/post/2025/swiftui-mac-2025/)

Title bar and search:
- In the default `TabView` style "the tab bar sits in the toolbar and the window title is hidden"; `sidebarAdaptable` shows the window title, and `navigationSubtitle` adds a subtitle. — [troz.net: SwiftUI for Mac 2025](https://troz.net/post/2025/swiftui-mac-2025/)
- Wrapping content in a `ScrollView` "made the title bar transparent, so content scrolls up behind it" and the author found this "looked like a layout error much of the time"; "the blur behind toolbars and title bars often looks like a layout error." — [troz.net: SwiftUI for Mac 2025](https://troz.net/post/2025/swiftui-mac-2025/)
- Hidden title bar: on macOS 26 `.windowStyle(.hiddenTitleBar)` left a blank strip at the top; fix `.containerBackground(.clear, for: .window)`; with `NavigationSplitView` the sidebar title must be removed with `.toolbar(removing: .title)`. — [fatbobman: Zipic retrospective](https://fatbobman.com/en/posts/zipic-3-technical-details/)
- Search: on Mac the toolbar search field "appears in the top-trailing position of the toolbar"; the system may minimize it into a button, with `searchToolbarBehavior` to opt in explicitly. — [WWDC25 323 transcript](https://nonstrict.eu/wwdcindex/wwdc2025/323/); `DefaultToolbarItem(kind: .search, placement: ...)` repositions the system search item, `DefaultToolbarItem(kind: .sidebar, ...)` the sidebar toggle. — [Peekaboo docs: SwiftUI New Toolbar Features](https://glama.ai/mcp/servers/@steipete/Peekaboo/blob/591abdd1ce3e464af59630d43f8d4379840354e3/docs/SwiftUI-New-Toolbar-Features.md)
- "Use layout guides and safe areas. Make sure you specify safe areas for your content so the system can automatically adjust the window controls and title bar in relation to your content." — [Apple: Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)

Making brand color work under glass chrome:
- "Avoid tinting all your elements. When every element is tinted, nothing stands out ... If you want to imbue color into your app, do it in the content layer instead." Tint "generates a range of tones that are mapped to content brightness underneath the tinted element. It draws inspiration from how colored glass works in reality." — [WWDC25 219](https://developer.apple.com/videos/play/wwdc2025/219)
- Sidebar glass picks up ambient color: "Light from colorful content nearby can subtly spill onto its surface." — [WWDC25 219](https://developer.apple.com/videos/play/wwdc2025/219)
- "Review your use of color in controls. Be judicious with your use of color in controls and navigation so they stay legible. If you do apply color ... define a custom color with light and dark variants, and an increased contrast option for each variant." — [Apple: Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)
- Background extension: "A background extension effect creates a sense of extending a background under a sidebar or inspector ... mirrors the adjacent content ... and applies a blur to maintain legibility." Apple's incorrect example: "the image next to the sidebar doesn't extend beneath it, so the sidebar floats above an empty background." — [Apple: Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)
- A plain color works with the effect: `ZStack { colorForTint.opacity(0.2).backgroundExtensionEffect(); content }` "extends a background color under the sidebar." Glass "looked better in dark mode than with the author's gradient"; "Test glass effects against real backgrounds, since they look less glassy on plain colors." — [troz.net: SwiftUI for Mac 2025](https://troz.net/post/2025/swiftui-mac-2025/)
- "Consider aligning the shape of controls with other rounded elements ... using rounded shapes that are concentric to their containers" (`ConcentricRectangle`, `rect(corners:isUniform:)`). — [Apple: Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)
- Legibility critique of the "content over tools" philosophy (relevant to a tool-heavy app): Adam Engst: "controls are not tools"; Nick Heer: "they bleed into your document, thus gaining a similar level of importance as the document itself"; Keren Bell: "It's not really readable because of the blur ... It leaves more space for content behind it, but takes up more space on its own." — [Michael Tsai: Liquid Glass: Content vs. Controls (Oct 2025)](https://mjtsai.com/blog/2025/10/16/liquid-glass-content-vs-controls/)

### Inferences
- The "title and + button floating oddly" symptom matches two documented causes: (a) a custom toolbar/window background or opaque content strip that stops the scroll-edge effect and leaves the glass pill hovering on flat color (Apple's "floats above an empty background" incorrect example), and (b) a single auto-grouped pill holding unrelated items. The documented remedies are: remove custom toolbar backgrounds; run brand color edge-to-edge under the toolbar/sidebar (`backgroundExtensionEffect` on a hero/background, `containerBackground(.clear, for: .window)` with hidden title bar); group with `ToolbarSpacer(.fixed)`; give the single primary action `.confirmationAction` or a tint and leave everything else monochrome.
- For a hidden-title-bar layout, the intentional-looking macOS 26 pattern from Apple's own sample is: leading area = sidebar toggle (system); center = nothing or an in-content heading rather than a toolbar title; trailing = `ToolbarSpacer(.flexible)` then grouped secondary actions, then search in the system top-trailing slot. Put the window's "title" inside the content layer (large heading on the brand surface) so the toolbar carries only actions.
- Brand color belongs on cards, backgrounds, and hero areas (content layer) with regular materials, while glass sidebars/toolbars will pick up that color by sampling it — so a warm, colorful app can look very on-brand on 26 without any tinted glass.

### Gaps
- No source describes a precise recipe for a `.hiddenTitleBar` + unified toolbar + `navigationTitle` layout on macOS 26 (title placement behaviors with `toolbarTitleDisplayMode` on Mac); Natalia Panferova's macOS toolbar styles guide could not be fetched (permission not granted).
- No Apple document found that describes toolbar title/search behavior changes specifically for AppKit `NSWindow` with `titleVisibility = .hidden` on 26.
- `DefaultToolbarItem` availability and macOS placements were taken from a third-party doc, not Apple's symbol page.

## Key question 3: How to opt out or constrain (UIDesignRequiresCompatibility, older SDK) and the tradeoffs

### Takeaway
`UIDesignRequiresCompatibility = YES` or building with Xcode 16 keeps the pre-26 look on macOS 26, but Apple labels the key temporary and ignores it when building for macOS 27, so it buys at most one release cycle; the user-side alternatives (Reduce Transparency, the 26.1 Clear/Tinted setting) are not under the app's control but must be tested.

### Cited Findings
- "Warning: Temporarily use this key while reviewing and refining your app's UI for the design in the latest SDKs." "If YES, the system runs the app using a compatibility mode for UI elements. The compatibility mode displays the app as it looks when built against previous versions of the SDKs." "Absence of the key, or NO, is the default value for apps linking against the latest SDKs." "The system ignores this key when you build for iOS 27 or later, iPadOS 27 or later, Mac Catalyst 27 or later, macOS 27 or later, or tvOS 27 or later." Availability: iOS/iPadOS/macOS/tvOS 26.0+. — [Apple: UIDesignRequiresCompatibility](https://developer.apple.com/documentation/bundleresources/information-property-list/uidesignrequirescompatibility)
- "To update and ship your app with the latest SDKs while keeping your app as it looks when built against previous versions of the SDKs, you can add the UIDesignRequiresCompatibility key to your project's Info pane." — [Apple: Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)
- Qt's two workarounds for Liquid Glass problems in native styles: "Building the application with Xcode 16" or "Setting the UIDesignRequiresCompatibility key to YES," which keeps "the existing look and metrics of earlier macOS releases." — [Qt blog: Qt on macOS 26 Tahoe](https://www.qt.io/blog/qt-on-macos-26-tahoe)
- User-side: Reduce Transparency "disables all Liquid Glass effects and restores the traditional menu bar and Dock"; Increase Contrast "is automatically paired with Reduce Transparency" and outlines controls; 26.1 adds Clear vs Tinted. — [Eclectic Light Co.](https://eclecticlight.co/2025/11/05/appearance-revisited-get-tahoe-26-1-looking-in-better-shape/)
- Apple: "people can choose a preferred look for Liquid Glass in their device's settings, or turn on accessibility settings that reduce transparency or motion ... Ensure you test your app's custom elements, colors, and animations with different configurations of these settings." — [Apple: Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)
- watchOS exception shows the SDK-gating logic: "Liquid Glass changes are minimal in watchOS, so they appear automatically ... even if you don't build against the latest SDK." (By implication, on macOS the new look requires the 26 SDK.) — [Apple: Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)

### Inferences
- Opting out via the key is a bridge, not a strategy: the app will be forced onto the new design with the macOS 27 SDK. Building with Xcode 16 also blocks all macOS 26 APIs (and eventually App Store SDK requirements), so it is only viable for a short window.
- The practical middle path is to ship with the 26 SDK, keep standard chrome (so it is glass on 26 and classic on 14/15), and confine the brand expression to the content layer, which looks correct under both systems and under Reduce Transparency.

### Gaps
- No Apple statement found on the App Store's Xcode 26 SDK submission deadline for macOS apps (which would bound the "build with older SDK" option).

## Key question 4: What does Apple say about color and motion in Liquid Glass?

### Takeaway
Apple's color rule is "color in the content layer, tint only the one primary action"; its motion rule is that glass morphs rather than fades (`matchedGeometry` and `materialize` transitions, buttons morphing into menus/popovers), and custom glass motion must be coordinated inside a `GlassEffectContainer` with `glassEffectID`.

### Cited Findings
Color:
- "Tinting should only be used to bring emphasis to primary elements and actions in the UI." "If you want to imbue color into your app, do it in the content layer instead." — [WWDC25 219](https://developer.apple.com/videos/play/wwdc2025/219)
- Regular variant "provides legibility regardless of context. It works in any size, over any content and anything can be placed on top of it." Clear "is permanently more transparent ... needs a dimming layer" and should be used only over media-rich content with bold, bright content on top; "They should never be mixed." — [WWDC25 219](https://developer.apple.com/videos/play/wwdc2025/219)
- "Assign a tint color to suggest prominence." — [Apple: Applying Liquid Glass to custom views](https://developer.apple.com/documentation/swiftui/applying-liquid-glass-to-custom-views)
- Tinted toolbar items: "use this to convey meaning, like a call to action or next step, but not just for visual effect." — [WWDC25 323 transcript](https://nonstrict.eu/wwdcindex/wwdc2025/323/)
- Accent: `glassProminent` "uses the accent color or the user's chosen theme color" by default. — [troz.net](https://troz.net/post/2025/swiftui-mac-2025/)
- App icons: provide layered icons via Icon Composer; macOS offers default, dark, clear and tinted variants that the user can choose. — [Apple: Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass); in 26.1 "The Clear style decolourises most icons, making them hard to read." — [Eclectic Light Co.](https://eclecticlight.co/2025/11/05/appearance-revisited-get-tahoe-26-1-looking-in-better-shape/)

Motion:
- "As you go between states in an app, Liquid Glass dynamically morphs between the controls in each context." "Instead of fading, Liquid Glass objects materialize in and out by gradually modulating the light bending and lensing." "Liquid Glass responds to interaction by instantly flexing and energizing with light." — [WWDC25 219](https://developer.apple.com/videos/play/wwdc2025/219)
- "buttons fluidly morph into menus and popovers"; slider/toggle knobs "transform into Liquid Glass during interaction." — [Apple: Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)
- Custom morphing: `GlassEffectContainer(spacing: 40)` with `HStack(spacing: 40)` and `glassEffectID("pencil"/"eraser", in: namespace)`; toggling with `withAnimation` morphs the eraser into the pencil "when the eraser's nearest edge is less than or equal to the container's spacing." Use `.materialize` for effects farther apart than the container spacing. "To provide people with a consistent experience, use matchedGeometry and materialize transitions across your apps." — [Apple: Applying Liquid Glass to custom views](https://developer.apple.com/documentation/swiftui/applying-liquid-glass-to-custom-views)
- Windows: "split views automatically reflow content for every size using beautiful, fluid transitions." — [Apple: Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)
- Reduce Motion / Reduce Transparency "can remove or modify certain effects"; standard components adapt automatically, custom ones must be tested. — [Apple: Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)

### Inferences
- For a "warm, colorful, animated" app the Apple-sanctioned place for color is cards, backgrounds, illustrations and data (content layer) using standard materials; for motion, the sanctioned place for custom glass morphing is a small cluster of floating controls (a floating action pill, a mode toggle) inside one container, not the whole UI.

### Gaps
- No Apple numeric guidance (durations, spring parameters) for glass morphing was found; the transitions are system-defined.

## Key question 5: Performance and visual bugs reported on macOS 26.0–26.x and fixes

### Takeaway
Reported macOS 26 issues cluster around toolbar/title-bar overlays (clicks swallowed by `NSGlassContainerView`, blank strips with hidden title bars, accessories covering sidebars under Reduce Transparency), beta-era `glassProminent` glitches, and Apple's own warning that too many glass effects or containers degrade rendering performance.

### Cited Findings
- Clicks swallowed: On macOS 26, SwiftUI buttons overlaid on the title bar/toolbar area "don't receive clicks"; cause traced to a new `NSGlassContainerView` inside `NSToolbarView` that returns itself from `hitTest:`. Reported on betas and on macOS 26.0.1; filed as FB18201935; no Apple response in thread. Workarounds: `.buttonStyle(.borderless)` (worked for one commenter on 26.0.1), or swizzling `hitTest:` on the private class (fragile). — [Apple Developer Forums thread 788928](https://developer.apple.com/forums/thread/788928)
- Hidden title bar blank strip: `.windowStyle(.hiddenTitleBar)` left a blank strip at the top on macOS 26 (not visible in previews); fixed with `.containerBackground(.clear, for: .window)` (macOS 15+). — [fatbobman: Zipic retrospective](https://fatbobman.com/en/posts/zipic-3-technical-details/)
- Titlebar accessory covers sidebar: with Reduce Transparency on, an `NSTitlebarAccessoryViewController` "can visually cover the first row of a sidebar" on macOS 26; `preferredScrollEdgeEffectStyle = .hard` (macOS 26.1+) gives a hard edge on the titlebar accessory but not on `NSSplitViewItemAccessoryViewController`; filed FB22887367, no confirmed fix. — [Apple Developer Forums thread 827686](https://developer.apple.com/forums/thread/827686)
- Beta-era: "The glassProminent button showed a weak mouse-down effect with some tints." "A graphical glitch in glassProminent appeared with ScrollView. Fixed in Beta 5." Sidebar toggle removal failed inside a navigation view. — [troz.net: SwiftUI for Mac 2025 (betas 4–5)](https://troz.net/post/2025/swiftui-mac-2025/)
- Apple performance guidance: "Creating too many Liquid Glass effect containers and applying too many effects to views outside of containers can degrade performance. Limit the use of Liquid Glass effects onscreen at the same time." — [Apple: Applying Liquid Glass to custom views](https://developer.apple.com/documentation/swiftui/applying-liquid-glass-to-custom-views); "Combine custom Liquid Glass effects to improve rendering performance" using `GlassEffectContainer`; "Performance test your app across platforms." — [Apple: Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)
- `backgroundExtensionEffect` should "often be used with only a single instance of background content with consideration of visual clarity and performance." — [Apple: backgroundExtensionEffect()](https://developer.apple.com/documentation/swiftui/view/backgroundextensioneffect())
- Safari darkens video under glass media controls on macOS 26 ("Darkening videos brings less focus to content!" — Jeff Johnson; debug flag "Hosted blur material in media controls"). — [Michael Tsai: Content vs. Controls](https://mjtsai.com/blog/2025/10/16/liquid-glass-content-vs-controls/)
- Qt reported Liquid Glass "posed challenges for Qt's native styles" with some issues possibly remaining; recommends the compatibility key or Xcode 16 as workarounds. — [Qt blog](https://www.qt.io/blog/qt-on-macos-26-tahoe)
- 26.1 inconsistencies: Tinted mode "produced inconsistent changes in Finder and Tips toolbars"; author notes Liquid Glass "is applied to sidebars but not toolbars" in that comparison. — [Eclectic Light Co.](https://eclecticlight.co/2025/11/05/appearance-revisited-get-tahoe-26-1-looking-in-better-shape/)
- Newer toolbar APIs now listed for the following release (iOS/macOS 27): `toolbarMinimizeBehavior`, `contentMarginsRemoved(_:)`, `ForEach` conforming to `ToolbarContent`, `ToolbarPlacement.statusBar` — i.e., the 26 toolbar API set is still being filled in. — [Michael Tsai: SwiftUI Toolbars (Sep 2026)](https://mjtsai.com/blog/2026/09/08/swiftui-toolbars/)

### Inferences
- The specific bugs most likely to bite a hidden-title-bar, custom-chrome Mac app are the overlay click-swallowing (any custom view placed in the title bar region) and the blank-strip issue; both have known mitigations (`.borderless` style; `containerBackground(.clear, for: .window)` + `toolbar(removing: .title)`).
- Because the 26.1 user setting can make glass more opaque ("Tinted") or fully disable it (Reduce Transparency), the app must look correct when its chrome is an opaque gray bar, which again argues for keeping color on the content layer.

### Gaps
- No systematic changelog of Liquid Glass fixes per point release (26.0 → 26.7) was found; Apple release notes were not fetched, and the macOS point-release search returned only spam/aggregator pages. A follow-up pass against Apple's macOS 26.x release notes is needed for a version-by-version list.
- No quantified performance measurements (frame times, GPU load) for glass on Mac hardware were found in the sources reached.

### Takeaway

### Cited Findings
