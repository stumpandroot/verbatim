# Verbatim design rules

This file is the brand spec for every Verbatim surface: the Mac app, the iPhone app, the keyboard, the dictation bar, the menu bar, widgets and Live Activities, the app icon, and the website. Agents read it before changing any UI. If something you need isn't here, ask; don't invent a color, a typeface, an icon, a material, or a radius.

Sources: the family design system (project doc `01-design-system.md`, v2.1), the brand marks decision (`brand/README.md`, October 18, 2026), the interface icon set (October 18, 2026), Tim's Home review (October 22, 2026), his Home feel choices the same day (sharp corners, stacked tiles, full motion), and the website-style mockup for the Mac app ("The app, in the website's clothes", October 23, 2026; §11). `mac/tools/brand-check.sh` enforces the rules marked **[checked]**.

## 1. Color

The palette lives in `mac/Verbatim/Views/Tokens.swift` (`Ink`). Use tokens only. **[checked]** No hex values outside `Tokens.swift`, and no `Color.red`, `.blue`, `.orange`, `.green`, `.gray`, `.purple`, `.pink`, `.yellow`, or `.accentColor` outside it. Errors and destructive actions use `Ink.danger` (defined in Tokens.swift), with an icon and a word, never persimmon.

| Token | Hex (light) | Means | Use it for |
|---|---|---|---|
| `paper` | `#F5F0E6` | The page | App background |
| `reader` / `card` | `#FFFDF9` | Content you read | Transcript sheet, neutral cards, rows |
| `ink` | `#26352E` | Structure | Text, strokes, primary buttons (`interactive`) |
| `persimmon` | `#FA6B47` | **Record** | Record panel, voice-note chips, recording state, today's bar in This week, the app icon |
| `butter` | `#F4C76B` | **Dictate** | Dictate tile |
| `sage` | `#AFC398` | **Import** (files and links) | Import tile, imported-file and link chips |
| `petal` | `#EFB6C8` | **App audio** | App audio tile, app-audio chips |
| ink outline on `card` | — | **Live captions** | Live captions tile and its chips |

Neutral (`ink` at 6% with `dim` text, plus the item's own diagram or initials): kinds (journal, thoughts, meeting, note, podcast, video, talk, interview, brain dump, audio only), plans (§17.7), tags, projects, filters, counts, the transcript's unclear chips (§15), and the icon tiles on settings rows (the wash with an ink glyph; destructive rows keep the wash with the `danger` glyph and word). They never borrow an action hue.

Speaker pills in a transcript are the one exception: they may use the four panel colors (`panelRecord`, `panelPetal`, `panelSage`, `panelButter`) in a fixed rotation by speaker order (first speaker record, then petal, sage, butter, and around again), with ink text and the speaker's name. The name carries the meaning; the hue only tells speakers apart. Everywhere else, color still means a capture mode.

Reading washes are a separate role and appear only on the transcript and document surfaces, never beside the action tiles: saved = `saved` (butter), playing = `playing` (sage), search match = `match` (persimmon). Playback controls follow the playing color: the player's play disc and the played part of its waveform are `panelSage` with ink glyphs; bookmark ticks on the waveform stay butter.

Rules:

1. One color, one meaning. Never reuse a hue for a different action on the same screen. Tags, filters, and counts are neutral (filter chips use the `chip` wash, §11). Two exceptions: project cards on color panels (§11), which cycle butter, petal, and sage as decoration (their text and eyebrow say "Project", so the hue never stands alone), and speaker pills in a transcript, which rotate record, petal, sage, and butter (above; the name is always on the pill).
2. About 70% neutral, 20% ink, 10% accent on working screens. Home and onboarding may run richer.
3. One saturated fill per screen: persimmon, for the primary action. The pastel start tiles on Home (butter, sage, petal) are allowed because each one is a different action; everything else is a tint, a color panel (§11), or neutral.
4. Text on paper uses `ink`, `dim`, `mute`, or a text-safe variant (`accentText`, `sageText`), never a bright fill.
5. Text on every fill is ink: petal 7.5:1, butter 8.1:1, sage 6.8:1, persimmon 4.45:1 (so on persimmon, ink text must be 18 pt or larger, or semibold 14 pt or larger). Never put reader white text on persimmon; it measures 2.8:1.
6. Status never depends on color alone; pair it with a word or an icon.
7. Dark mode is a near-black green, never an inversion. Color panels get slightly deeper fills in dark only (`panelRecord` `#E2694B`, `panelButter` `#DDB563`, `panelSage` `#9DB088`, `panelPetal` `#D9A3B5`; light uses the brand values, with `panelRecord` = the Record fill `#FB7350`). Ink text stays on them in both modes.

## 2. Type

| Role | Font | Where |
|---|---|---|
| Display | `Ink.serif` (New York stands in for Instrument Serif) | Greeting, Record, section titles, document titles, big numbers |
| UI and body | SF Pro, Dynamic Type | Everything else: tile names, labels, rows, buttons, transcript text |
| Data | `Ink.mono` | Keyboard shortcuts, timecodes and durations, running recording timers, file paths, tabular indexes ("01"), and in the website style (§11) eyebrows ("◇ This week"), page-title counts ("46 transcripts"), day headers, and a list's status column. Never smaller than 12 pt. |

Rules:

1. Sentence case everywhere. No uppercase tracked labels except `Overline`, at most one per screen.
2. Metadata lines are sans, not mono: "Voice note · 7:50 · Today". Use `.monospacedDigit()` for numbers that change. **[checked]** In files marked `// brand: web style`, mono text is never smaller than 12 pt (`Ink.mono` sizes, `Keycap` sizes, no `Overline`).
3. Shortcuts render as keycaps: mono inside an outlined rectangle with the button radius (4).
4. Never set reading text in the serif, except on screens built on the refined kit, where transcript reading text is serif (§13).
5. Button names: SF Pro semibold (13.5 pt in a regular pill, 12 pt in a mini). Mac Home's tile names are serif 21 pt with a 12 pt sans detail (§6.5).

## 3. Icons

- **Ours (`BrandArt`) for anything that means something in Verbatim:** record, dictate, import, link, app audio, captions, library, moments, bookmark, play, export, summaries, speakers, language, voice, search inside a transcript, empty states, and all navigation. Fine line: a 24-unit grid with a 1.5 stroke, or a 112-unit box with a 6 stroke. Round caps and joins.
- **Apple's SF Symbols only for standard controls.** **[checked]** Allowed: `xmark`, `xmark.circle.fill`, `plus`, `plus.circle`, `minus.circle`, `chevron.*`, `checkmark`, `checkmark.circle.fill`, `ellipsis`, `ellipsis.circle`, `square.and.arrow.up`, `trash`, `magnifyingglass` (search fields only), `sidebar.left`, `line.3.horizontal` (drag handles), `arrow.right` (text links), `arrow.up.arrow.down`, `chevron.up.chevron.down`, `arrow.uturn.backward`, `arrow.counterclockwise`, and keyboard keys (`return`, `delete.left`, `globe`, `keyboard`, `shift`, `shift.fill`, `capslock.fill`).
- Everything else, such as `sparkles`, `wand.and.stars`, `waveform`, `mic`, `bookmark`, `link`, `play.*`, `note.text`, `doc.on.clipboard`, and `info.circle`, gets a `BrandArt` glyph. If none exists, draw one in the same grammar and add it to `mac/tools/gen_icons.py`.
- **System surfaces** (Control Center controls, Live Activities and the Dynamic Island, widgets, context menus, the menu bar item) can only show SF Symbols or custom symbols from the asset catalog. Export our glyphs as custom symbols (`.symbols` in Assets) and use those; until a glyph is exported, the closest SF Symbol is allowed there, marked on its line with `// brand: system surface`. The menu bar item uses the bars mark. Exported (`mac/tools/gen_symbol.py`): `thought`, `mark`, `marked`, `record` (capture), `dictate` (Dictations), `captions`, `bars` (the bars mark, filled), and the Mac's Record As symbols (§17.6), including `rec.braindump` and `rec.audio`. Every Control Center control uses them, so Control Center shows one family: the session switch `bars`, Record `record`, Dictate `dictate`, New thought `thought`. The Action button's control takes the name and symbol of what you chose in Settings › Action button ("Record or mark" with `mark`; `Ribbon.actionControl`), which the app mirrors into the App Group; the controls gallery, and a control the app hasn't named yet, say Verbose action.
- Icons sit bare. Home's start tiles and Record panel have no disc behind the icon. Elsewhere an icon may sit in a tinted disc of its own color; never put a white disc on a colored tile.
- **Diagrams:** Capture (rings), Refine (paths into lines), and Understand (overlapping circles). Use them in onboarding, the iPhone's Method cards, empty states, and loading. On Mac color panels they become the panel drawings (§11: rings, lines, circles, strands). Don't use them as wallpaper. Ink strokes on paper or on their own fill.

## 4. Marks and the app icon

- **App icon:** the notation bars (B1), dimensional: white bars with depth and a soft shadow on a persimmon-red field that lightens toward the top left (Tim's render, October 23, 2026). Masters: `brand/verbose-app-icon-render-1254.png` (source), `verbose-app-icon-1024.png` (iPhone, full bleed), `verbose-app-icon-mac-1024.png` (Mac shape). The flat paper-on-persimmon bars stay the mark everywhere else (sidebar, website, favicon).
- **Colophon:** the tangent rings (R3a), for the website, onboarding, About, and print. Never as the app icon.
- Public name: Verbose. Wordmark: lowercase 'verbose.' in the serif, persimmon period. Tagline: 'Go ahead. Be verbose.' 'Verbatim' is the internal codename.
- **In-app wordmark:** the bars plus lowercase "verbose." in the serif, as in the sidebar (`Ink.wordmark`). The period is a mark in the text-safe persimmon (`accentText`, 5.1:1 on paper); the bright `persimmon` measures 2.5:1 on paper, too low for a small mark. The tagline (`Ink.tagline`) sits under it in the serif on About and the first onboarding screen.
- **Retired:** the V wing mark (`BrandArt.mark`). It must not appear anywhere.
- One color per mark: persimmon, ink, or paper.

## 5. Surfaces and glass

1. **[checked]** Never put text on a blur or material (`.ultraThinMaterial`, `.regularMaterial`, `.glassEffect`). Glass belongs to system chrome: toolbars, tab bars, sheets, and transient controls without text. A floating bar with text uses `Ink.bar` or `Ink.card` plus a hairline.
2. Paper, illustrations, and colored tiles stay opaque.
3. Radii (sharp, `Radius` in Tokens.swift): 4 for filter chips, fields, and keycaps; 6 for rows and sheets; 8 for tiles and cards; 10 for the Record panel, color panels, and big strips. Buttons are pills (capsules), and so is the search field (§11). Use the tokens, never a number. Don't round everything the same. On iPhone, `.phonePrimary` and `.phoneSecondary` draw the dark and line pills (28 pt, 36 pt when large), and grouped lists (Edit Home, Tab bar) use `phoneGroupedList()`, whose cards take `Radius.tile` instead of the system's inset grouped corners.
4. Shadows: a hairline, or the website's hard offset shadow (`Ink.hard`, no blur) under an ink-outlined card or highlighted row (§11). No soft shadows everywhere.
5. Color panels (§11) are opaque brand fills with paper grain; grain never goes on paper, cards, or under glass, and it turns off under Increase Contrast and Reduce Transparency.

Until the look switch goes, each look keeps its own Edit Home layout (`Model/HomeLayout.swift`), and Home draws the one for the look on screen.

1. **Stats appear in one place only** (This week). Whole cards are buttons: This week opens You (iPhone: the You page in Settings).
2. **iPhone Home** (`VerbatimPhone/HomeScreen.swift`, `HomeSections.swift`), top to bottom: the date over the large serif greeting ("Good evening, Tim.", `LargeSerifTitle`), the What's new banner after an update, then Edit Home's sections in its order and sizes, and Edit Home at the end. By default: the persimmon **Record card** (`RecordCardFace` under the Record tray's press: a tap records a voice note, touch and hold opens Record as; VoiceOver reads one button with each way to record as an action; "Ready · iPhone Microphone", then "Recording" or "Paused" while one runs, when a tap brings the recorder back); the four **tiles** two by two (`ColorTileFace`; Import is a menu of Photos, files, or a link); **This week** as one slim line (`WeekCard`, Compact); and **Recent** (serif, with See all) as the three newest in a card with their kind's badge, the kind and time, and the length (`PaperRow`). Compact sizes: the Record card is one slim row, the tiles one row of four, This week Large is the card with the bars beside the numbers, and Recent lists one line each with the kind's dot. A recording with filler words shows Clean up, which opens its Cleaned text. The navigation bar is hidden (Home draws its own title); the tab bar is each look's. In Native, Record's tab bar accessory steps aside on Home's own screen while the Record card is shown and nothing is recording (`HomeSpacing.hidesRecordAccessory`); on every other tab, while recording, and with the card hidden, it stays.
3. **Mac Home** (`Views/HomeView.swift`, `HomeSectionsMac.swift`): one column, at most 860 pt wide with 56 pt margins (32 in a narrow window), left-aligned under the toolbar. The date over the serif greeting, the What's new line, then the sections. By default: the **Record card** across the column (a click records a voice note; right-click has Record As and the microphone; its hint names ⌥⇧R); the four **tiles** in one row with their shortcuts at the end of the name (Dictate's key and "hold", ⌘O, ⌃⌥P; "Needs Accessibility" in Dictate's place when it does; a file held over Import says "Drop to transcribe"), each with its popover and right-click menu as before; then **Recent** (a card: the serif title with Library, four rows of the kind's dot, the title, the kind and day, and the length) beside **This week** (the card: the words, "words, 20 recordings", the time saved and the week's moments, and seven bars, today's in persimmon). Two Large neighbors that can pair share a band, two thirds and one third, at the same height (`HomeRows`: Recent recordings, This week, Today's thoughts, and Journal pair; the Record card and the tiles always run across); a window narrower than 560 pt of column stacks them. While you record or capture an app's audio, the Record card becomes the **recording card** (`RecordingCard`, mockup MacRecorder): the dot, "Recording a voice note" (or the kind, or "Capturing Zoom"), the microphone and "Saved as you go", the clock, the live waveform, your words in the serif, then Mark moment with its shortcut, Pause, the moments so far ("Marked 0:31 · 1 moment" for two seconds), and Stop and transcribe (⌥⇧. ; Cancel while the microphone starts). With the Record card hidden, the recording card leads Home anyway. Edit Home outlines each section with a dashed ink edge and its name, and opens the inspector beside Home.

At most three are colored; a fourth colored pick is the card. The Palette setting (§13) turns the fills to tints.
5. **Today's thoughts and Journal** (hidden until you show them): Large is the serif title with its link (Today's page, By day) over a card, the latest four thoughts with their times, or the newest entry with a play button and this week's days as ink dots; Compact is one slim card row. New thought is a quiet button, never a second persimmon fill beside Record.

## 7. Motion

- Use the `Motion` tokens. Ease-out or critically damped springs; no bounce in productivity controls.
- Never animate keyboard-initiated or high-frequency actions.
- Cards tilt toward the pointer, lift 2 pt, and catch a sheen and an edge light on hover, and press in (0.98) on click or touch (`CardMotion`, `HomeCard`). Keep hit-testing on a flat, untransformed layer: a 3D-rotated view loses clicks on macOS 26. iPhone has no hover, so cards only press. Refined screens (§13) don't tilt: their cards and tiles only press (`RefinedPress`).
- Home's Record meter and its hover and touch listening retired with the refined Home (§6, §13): the Record card's rings breathe instead, and the Mac's recording card shows the real level only while you record.
- The Method diagrams loop slowly (iPhone): Capture's rings swell, Refine's strands flow into clean lines, Understand's circles drift together and apart. On Mac the panel drawings loop (§11), at most one per screen.
- Loops (the breath, the diagrams, the panel drawings) use TimelineView with a Canvas, at most 30 frames a second, and pause when they're off screen or the app is inactive (`LoopTimeline`). Never drive a loop with state or a repeatForever animation; on macOS 26 every SwiftUI transaction is expensive.
- Big cards (Record, tiles, color panels, This week) tilt as above and, on Mac, pick up the 1.5 pt ink outline and a hard shadow on hover: (7, 9) under the pointer, (2, 3) while pressed. Flat list rows never tilt; they take the outline and a (4, 5) shadow on hover or selection (§11).
- Screens arrive at once: no entrance stagger on navigation, so a screen never makes you wait for its content. On iPhone that means no row rise-in, no stagger, and no tab entrance.
- **Haptics** (iPhone, its keyboard, and Apple Watch; the Mac plays none). One cause, one haptic, always with something you can see. Which haptic an event plays is `HapticPolicy` (`Model/HapticPolicy.swift`, checked by `tools/test-haptics.sh` and the iPhone's self-test); the app plays through `Haptics` (`PhoneMotion.swift`), the keyboard through `KeyboardModel`, and the watch through `WatchRecorder`. Only system feedback generators and `.sensoryFeedback`, so System Haptics and Accessibility › Touch › Vibration turn them off too. Settings › Personalization and preferences › Haptics (on by default, per device) turns every one off; it lives in the App Group so the keyboard reads it, and the watch gets it in the iPhone's context (`WatchContext.haptics`).
  - **Start:** medium impact at 0.7, played just before the microphone opens (Record, the tray, New thought, Live captions, a keyboard session). **Stop:** soft impact at 0.8 at the tap (Stop, Stop & add, Discard, Live captions' Stop or Save), not after saving; Saved and Thought added play nothing more.
  - **While recording:** pause and resume are a light tap (pause after the audio stops being written, resume before it starts again). Mark is a light tap at 0.5 while `HapticPolicy.markBuzzes` is true; Tim checks a test recording on the built-in mic and on AirPods, and if the tap can be heard, it goes to false and Mark confirms with "Marked 4:12" only. Every recording session sets `allowHapticsAndSystemSoundsDuringRecording` before it activates (`RecordingRoute.setCategory`), or iOS silences haptics while the microphone records.
  - **Results:** transcript ready (or a recording added to one) is `.success`, once per recording, only with Verbose in front and the "ready" message showing; a template that runs after it adds none. Your voice set up and Send to Reminders adding a plan's tasks ("Added 9 reminders to Studio") are the only other `.success`.
  - **Problems:** microphone not allowed, couldn't start, couldn't save, and transcription failed are `.error`. An automatic pause (a call, a route change, audio it can't save) and low storage at the start are `.warning`.
  - **Small things:** every copy, and a ribbon take Copied or Inserted, is one `.selection` tick. A note or bookmark added, a speaker suggestion used, and a move to a project are a light tap. Choices in a list, scrubber lines, and tray rows tick `.selection`. A badge change and Delete all data play none.
  - **Keyboard** (Allow Full Access only; without it nothing plays and nothing is read): dictation start and Done are the app's start and stop taps; Inserted, Copied, the format chip, and the polished swap tick `.selection`. Typing keys tap (light, 0.6) only with Settings › Keyboard › Typing haptics on, which is off by default.
  - **Apple Watch:** `.start` just before the microphone opens, `.click` on a mark, `.stop` once recording has stopped, `.failure` when it can't start.
  - **In the background** (the Action button, a widget, Control Center, Siri, Live Activity and Dynamic Island buttons) iOS plays no app haptic; Verbose doesn't try. The Live Activity shows the change instead.
- One screen is in the window at a time. A sidebar move swaps the screen instantly, with no fade. Opening or leaving a transcript slides the new screen 12 pt over 150 ms, opaque from its first frame; the old screen is gone at once. Limit Motion swaps every screen instantly. The Mac self-test counts the screens in the window after each change.
- Back comes back to the place, not the top (Mac, both looks): a transcript's Back (Verbose style: a mini line pill with `chevron.left`, named for where you came from, at the top left of the header; Native: the toolbar's Back and Forward), View › Back and Forward (⌘[ and ⌘]), and the mouse's side buttons return to the screen as you left it, already scrolled to where you were on its first frame, with the row you opened lit as selected (`App/NavTrail.swift`). The Library comes back that way from the sidebar too; Home only by Back.
- Icons arrive fully drawn and draw on again on hover. Icon draw-ons never loop.
- Sidebar rows: on hover a wash fades and scales in (180 ms, ease-out), the label nudges 2 pt right, and the icon redraws. The persimmon selection tick slides to the new row over 300 ms.
- Limit Motion (and the system's Reduce Motion) stills all of it: no tilt, lift, or scale, a still meter, still diagrams, icons fully drawn, and crossfades instead of slides.

## 8. Words

Google developer documentation style: second person, active voice, sentence case, serial commas, and no "simply", "just", "easily", "currently", or "soon". Name buttons with verbs ("Record", "Copy", "Transcribe again in…"). An accessibility label starts with the word the button shows ("Done", "Cancel dictation"), with any detail in the hint, so Voice Control's "Tap Done" finds it (WCAG 2.5.3, Label in Name); an icon-only button gets a label ("Done" for a checkmark). Sentence case holds in the iPhone's Native look too: navigation titles, cards, alert buttons, and widgets ("By day", "Tab bar", "Not now", "Today's thoughts"). Voice notes are "Voice note" everywhere you read them (the stored source stays `voiceMemo`).

The on-device promise has one phrasing everywhere (Templates, Ask, You): "On this Mac with Apple Intelligence. Nothing leaves it." (or "Counted on this Mac. Nothing leaves it." where no model runs), then the clause specific to the place, in SF Pro 12.5 `dim`, never mono. A Copy that confirms says "✓ Copied" (§6.6).

Every user-visible change adds an item to the `"next"` entry of `mac/ReleaseNotes/ReleaseNotes.json` in the same commit: its platforms (`mac`, `iphone`, `watch`), one line of about 12 words (at most 90 characters), and, when it helps, a one-sentence detail (at most 200) that opens when the line is tapped or clicked. Write in this style, present tense, with no platform prefix, exclamation points, or em dashes. What's new lists each app's own platforms first and folds the rest under one "Also on" row. CI stamps that entry with the build's run number; after the build ships, a follow-up commit sets its build number (`mac/ReleaseNotes/README.md`). Both apps show the notes in What's new.

## 11. Website style (Mac)

**Superseded for the apps by §13 (the refined look).** Screens that haven't moved to the refined kit still follow this section; it goes when the last Mac screen moves.

The Mac app wears the website's clothes (mockup "The app, in the website's clothes", October 23, 2026, `notes/web-style/playful.src.html`). Home and Library are done; every other Mac screen follows these rules when it's next touched. Build with the kit in `mac/Verbatim/Views/WebStyle.swift` and mark the file `// brand: web style` (brand-check then holds its mono text to 12 pt or larger).

**Titles**

1. The big two-line headline (serif 52, italic second line) is for Home only. Every other screen has a compact title: `PageTitle` (serif 34, a mono 12.5 count beside it such as "128 kept", controls and the search field on the right, an optional 14 pt dim lede under it).
2. Section titles are serif 26 with an italic second part ("Recent *recordings*", "Up *next*"), with an optional "Library →" text link (`SectionTitle`). Day headers are mono 12 with a dashed hairline ("Today · Fri Oct 23", `DayHeader`). Eyebrows are mono 12.5 with an outlined diamond ("◇ This week", `Eyebrow`), at most one per card.

**Lists**

3. List rows are flat (`FlatRowButton`, `flatRow(highlighted:)`): transparent on the paper with a hairline at the bottom and the row radius (6). Under the pointer or selected, a row takes the card fill, a 1.5 pt ink outline, and a (4, 5) hard shadow. **No tilt on rows.** Tilt stays on big cards: Record, tiles, color panels, This week.
4. Library-style rows: the kind dot (`KindDot`: source fill, ink icon for the kind; links an ink ring), a serif 21 title with an italic part where the data allows (after the project's name), a 12.5 pt sentence-case meta line, the status in mono, and the length in mono ("15:39").

**Controls and status**

5. Buttons are pills (`PillButton`, `PillLabel`, `PillButtonStyle`): **dark** (ink fill, paper text), **line** (1.5 pt ink inset outline), regular 36 pt or **mini** 28 pt. On a color panel use the fixed ink pill.
6. Filters are soft chips (`FilterChip`): the 4 pt button radius, the `chip` wash, no border; selected is ink with paper text. Never a capsule. A type chip may carry its source's color as a 9 pt dot (links: an ink ring); kinds, tags, and platforms have no dot.
7. Speaker pills on transcript lines rotate the four panel colors in a fixed order (record, petal, sage, butter; §1) with the name in ink. They're the only colored pills that don't mean a capture mode.
8. Status is plain colored text, never a capsule (`StatusText`): "Cleaned" in `accentText`, "Original" and counts in `dim`, "✓ Video kept" in `keptText`, "Needs retry" in `danger`. A check or an icon may lead it; the word carries the meaning.
9. The search field is a pill with a 1.5 pt ink outline on card white (`WebSearchField`).
10. Mono labels are never smaller than 12 pt. **[checked]** in files marked `// brand: web style`.

**Panels and art**

## 13. The look

### The layer rule

- **Apple draws the chrome:** the system tab bar with Liquid Glass, toolbars, the Mac's sidebar, sheets, menus and context menus, alerts, switches, and segmented controls. ### Contrast

Every text pair the kit draws reaches 4.5:1 in light, dark, and both with Increase Contrast, and the marks that carry meaning reach 3:1 (`mac/tools/test-refined.sh`). Where the mockup's colors fell short, the kit changed them:

- A persimmon fill is #FB7350, not the mockup's #FA6B47 (ink on it measures 4.45:1); in dark it's #F27A57, because ink on the panels' deeper #E2694B measures 3.9:1.
- The Record card's hint and the Mac recorder's secondary line are full ink: ink at 80% measures 3.6:1 and #3E4A43 measures 3.4:1 on the fill.
- The ready chip lightens the fill (`chipFull`, 6.3:1) instead of darkening it (ink at 10% measures 4.1:1).
- On the Mac, an on switch in dark is #E2694B, so its white knob reads (the light accent text measures 2.3:1 there).
- The recorder's older words use `mute`, never `faint` (2.8:1). On the Mac's recording card, words still being heard are italic in the card's ink rather than lighter: any lighter ink on the fill measures under 4.5:1.
- Quiet actions on a persimmon fill (the recording card's Mark moment and Pause) sit on the ready chip's wash: the neutral wash measures 3.95:1 under Increase Contrast.
- Under Increase Contrast, cards take a `separator` edge (an off-white card on paper is about 1.1:1), and the player turns solid.

### Superseded: Verbose style and Native

Everything from here to §14 describes the two looks the refined look replaces. Screens that haven't moved still follow it; it goes when the last screen moves.

#### The Native look

Each device has a second look, Native (mockup "Verbose, in a native look", October 25, 2026), that reads like one of Apple's own apps. `AppLook` (`Views/Look.swift`) holds the choice per device, never synced: the App Group on iPhone (key `appearance.look`, values `verbose` and `native`), so the keyboard follows it with no setting of its own. New installs start in Verbose style; onboarding's Pick a look step and Settings › Appearance change it. A pick shows a small centered card in the new look ("Switching to Native…", its thumbnail, and a spinner) over a scrim of the new look's background; the look is stored once the card is up, everything rebuilds behind it, and the card fades out over the result (`Views/LookSwitch.swift`; under Limit animation the card appears at once and leaves with a fade, with no scaling). Everything in sections 1 to 12 describes Verbose style; Native replaces it as follows.

1. **No brand color in the chrome** (mockup "Verbose Native Redesign", October 27, 2026; iOS 27.2 and macOS 27, where Apple took brand color out of its own apps' chrome: Music's tabs went system blue, its widgets black). The accent is the system's: system blue on iPhone (the default accent, #007AFF and #0A84FF in dark, #0040DD and #409CFF with Increase Contrast; iPhone Native sets no tint at the root, so the system's own applies, `NativeInk.accent`), and on the Mac its accent color (blue by default). Tabs, links, selection, primary buttons, list and sidebar symbols take it; text on it is white. Recording is system red (`NativeInk.record`), flat, with no gradient or glow, and only on the record disc, the stop square, and the recording playhead. Destructive actions keep the system's destructive role, and the tab badge stays the system's. Switches are system green on iPhone, as in Apple's own apps, and the accent on the Mac (the macOS default). The brand stays in your words, the waveform, and the app icon.
2. **Stock everything else, all the way:** system lists (`.insetGrouped` for Home and Settings, `.plain` for the Library), system grouped and plain backgrounds, separators, and fills, `NavigationStack` with large titles and `navigationSubtitle`, the Liquid Glass `TabView`, toolbars, `Menu` with `ControlGroup` (Books-style) for a transcript's More and for Record as, segmented pickers, standard sheets with the drag indicator, `.borderedProminent` and `.bordered` faces, SF Pro (numbers in SF Pro bold with `.monospacedDigit()`; no New York serif, no SF Mono, never SF Pro Rounded heavy), and SF Symbols. No paper, grain, color panels, line art, ink outlines, hard or soft custom shadows, glows, gradient cards, or tinted icon circles.
3. **Branch at the kit, not the screen.** The iPhone kit (`PhoneWebStyle.swift`, `NativeLook.swift`) reads `@Environment(\.look)` and draws either look; `LookStyle` colors (`.lookInk`, `.lookCard`, …) resolve from the environment. Home, Library, the transcript header, Settings, and Appearance have Native layouts of their own. On iPhone, every tab but Settings is rebuilt in a new look (an identity per look on its navigation stack, as the Mac's `lookRebuild()` does), so a screen and its navigation bar never switch in place. Only the tab on screen rebuilds when the look changes; a tab you left keeps its look until you open it again. Settings isn't rebuilt, because the look changes from Settings › Appearance. Home's two layouts are separate screens with their own bar setup.
4. **Meaningful color goes.** Verbose style's hues say "this came from Dictate" or "this is Ginna"; in Native every such place keeps a word or a symbol.
5. **Text on glass, Native only.** Native follows Apple and puts text on system glass where Apple does: the tab bar and its bottom accessory, toolbars, menus, the player bars (both apps; glass with text, like Apple's players), and the scrubber's time bubble. Lists, cells, and reading surfaces stay opaque. §5.1 still holds for Verbose style. Keep scroll edge effects on, and check both ends of the glass slider, Reduce Transparency, and Increase Contrast on a device.
6. **The keyboard follows the look** chosen on that iPhone: Apple's gray keyboard in flat colors (an extension can't use the system keyboard's glass), SF Pro, and the system's blue (`KB.nativeAccent`) only on Tap to talk, the voice bars, and Done, like the system keyboard's return key. Text and glyphs on it are white. It reads the look once per appearance from the App Group, like the dictate button's settings; without Full Access it keeps Verbose style.
7. **What doesn't switch:** the app icon, the menu bar mark, the notch and Dynamic Island, Live Activities, and Control Center controls (the system draws those). Live Activities follow the Lock Screen's light or dark appearance instead (`VerbatimWidgets/ActivitySkin.swift`): paper with ink in light, the dark paper (`darkPaperFixed`, the app's near-black green) with paper text in dark. The persimmon Stop with ink, the voice bars, and the bars mark stay in both. Their buttons are capsules (§5.3), and their timers' frames hold "0:00:00", so a recording past an hour never clips (`Ribbon.timerWidth`).
8. **Widgets follow the look** (Home Screen, Lock Screen, StandBy, and the Mac desktop; `VerbatimWidgets/HomeWidgets.swift`). iPhone widgets read `AppLook` from the App Group; Mac widgets read the look from the snapshot the app writes (`WidgetSnapshot.swift`), and the app reloads every widget when the look changes. Verbose style draws its color panels (Record persimmon, Dictate and the Mac's Thought pad butter, Quick capture the persimmon tint), the serif, mono labels, and outlined paper cards. Native draws them black in light and dark, like Music's widgets in iOS 27.2 (mockup "Verbose Native Redesign", section 7; `containerBackground` black): white text, gray secondary text, SF Pro (bold with monospaced digits for This week's number), and the flat system red record disc in a gray ring as the only color; Dictate is a white mic in a gray ring, New thought a white pill, and today's bar is white. `NativeWidget.black = false` falls back to the system background (white in light, dark gray in dark) should Apple pull Music's change. The This week widget's Color option is left from Premium Native and does nothing in Native. In tinted and clear modes, on the Lock Screen, and in StandBy at night, both looks draw one color: the record disc, the bars mark, and today's bar are `widgetAccentable()`, and shape and type carry the look. Snapshot titles are cut to 60 characters, and Recent recordings marks them `privacySensitive()`. Gallery names are sentence case and unique ("Record and dictate", "Today's thoughts", and the Lock Screen's "Thoughts" beside the Home Screen's "New thought"). Mono labels are 12 pt or larger at full strength; a label on the persimmon panel is SF Pro semibold 14 in full ink (§1.5).
9. **[checked]** Brand-check skips Native look code for SF Symbols, system color names, glass, and mono sizes. Mark a whole file `// brand: native file`, a block between `// brand: native begin` and `// brand: native end`, or one line with a trailing `// brand: native`. Hex colors still live in Tokens.swift, and the retired mark stays retired.

## 15. Unclear audio

Noisy recordings (the lawnmower test, October 26, 2026; `notes/audio/noise-report.md`) mark what the engine couldn't hear instead of guessing silently. The rules live in `Transcription/UnclearRules.swift`; the views in `Views/NoisyAudioViews.swift`, shared by the Mac and the iPhone.

1. **The unclear chip.** Where speech was heard for 2 seconds or more and the engine wrote nothing it was sure of, the reading view shows a chip between the lines: "unclear" in SF Pro 12.5 medium and the time in `Ink.mono(12)` ("unclear 2:10"), `dim` text on `ink` at 6% in a capsule, 24 pt tall, in the text column. It's neutral: never persimmon, butter, sage, or petal, and never a warning color, because nothing is wrong; the audio was hard to hear. Click or tap it to play that spot. VoiceOver reads "Unclear audio at 2:10" with a hint that it plays. Exports leave it out unless Unclear markers is on, which writes "[unclear 2:10]" in the text.
2. **Best-guess words.** Words the engine gave under 0.35 confidence get a dotted underline in `mute`, nothing else: no color, no "(?)" in the text, so the line reads and copies as it is. Only while the line's word timings still match its text (no correction since). Never in exports or Copy.
3. **Transcribe again with Whisper Turbo** sits in the transcript's Actions menu on both apps, with Switch to <the other engine> once a version is kept. The iPhone's waiting line ("Waiting for your Mac", with Cancel) is the same neutral row: `ink` at 6% with `dim` text.
4. **Reduce background noise** is a checkmark item in the player's speed menu (both looks, both apps). It's off by default, kept per device, and changes only what you hear.

## 19. Ask

Ask (mockup "Library features", section 2, October 26, 2026) answers a question from your own recordings, with numbered citations (`Model/Ask.swift`, `Model/AskRecipes.swift`, `Transcription/AskEngine.swift`).

1. **Find first, then answer.** Verbose ranks passages (about 70 words of consecutive lines) in the scope: BM25 over the question's words, blended with NaturalLanguage sentence embeddings where the device has one for the recording's language. The best 12 or so (at most four from one recording, about 6,000 characters) go to Apple Intelligence with the question; it must answer from them only and cite each sentence ("[2]"). Citations that don't match a passage are dropped, a sentence left with none goes, and the rest are renumbered 1, 2, 3 in order of use. Digests and action-item questions read across the scope, newest recordings first. Nothing relevant: "Nothing in Thoughts · All time matches this question, so Verbose didn't answer." Without Apple Intelligence: the matching passages and a one-line reason.
2. **The index stays on the device.** Passages and byte-quantized vectors live in Application Support's "Ask Index" (left out of backups, never synced or uploaded). It updates in the background eight seconds after the library changes, one recording at a time, only recordings whose lines changed (a fingerprint), and never while something records or transcribes. A question never waits for it. Deleting a recording or moving it to Recently Deleted takes its passages out of the index at once, and answers and digests drop its citations (`AskCleanup`). Settings' Delete all data also removes the Ask Index folder, recent questions, recipes, their schedules, and digests (`AskData.eraseAll`).
3. **Scope chips:** All, This week (the last seven days), Thoughts, Meetings, and each project. This week combines with one source ("Thoughts · This week"); All clears both. Chips are neutral (§11.6; capsules in Native, title case).
4. **Mac.** ⌘K anywhere, Edit › Find in Transcripts (⌘F, the same panel on Search since the consolidation of October 28, 2026: one search field), or the sidebar's **Search or ask** field (Verbose style; it replaces the toolbar's search field there), opens the panel over a scrim: the field, a Search and Ask switch (an ink segmented capsule; Native, a pop-up), the chips, then the result. Search is today's search: it filters the Library behind the panel and lists matching lines; Return shows the Library. Ask answers on Return. Verbose style: a reader card with the ink outline and a (7, 9) hard shadow, citation chips (number, ink play disc, title, mono time; neutral card with a hairline, and the sage `playing` wash with an ink outline while one plays), the footer "On this Mac with Apple Intelligence. Nothing leaves it. Verbose found 9 passages in 2 recordings first, then answered from them.", Copy (it turns into "✓ Copied") and Save as recipe (line pills), and your recipes as chips. Premium Native: a white Spotlight-style panel, citations as rows with a play pill, and "From 9 passages in 2 recordings, answered on this Mac." Native keeps the toolbar's search field ("Search or ask"); Return there asks. A citation plays from its time in place; right-click opens the transcript at its line.
5. **iPhone.** Library › Ask (a tile beside Templates, or "Ask about “…”" under the search field): the question, the chips, the answer card ("Answer" eyebrow, citation chips or Native rows, "Runs on this iPhone with Apple Intelligence."), and the other passages under it. A citation opens the transcript at that line and plays it.
6. **Recipes.** Hidden until you turn them on (consolidation, October 28, 2026; `RecipesSetting`, `ask.showRecipes` per device): Ask's More menu on both apps and, on iPhone, Settings › Features › Templates › Recipes. While you have a recipe, it keeps running and Ask shows recipes whatever the switch says. Hidden, Ask has no Questions and Recipes chips, New recipe, Save as recipe, or Recipes row. A question with a scope (`recipes.json`, synced like templates). Make › Ask › Recipes on the Mac (cards with Run now and Schedule, and the selected recipe's latest digest) and Ask › Recipes on iPhone (Scheduled, Any time, Last digest). A weekly time (day and time) stays on each device. A scheduled recipe runs while Verbose is open (checked each minute on the Mac) or at the next open after its time, once however many weeks were missed; on iPhone also in a background app refresh. Each run is a digest on that device, with its citations, and a scheduled run posts a notification with the answer's first line. None are seeded; the empty state offers Weekly digest of my thoughts (Fridays, 4:00 PM), Action items from this week's meetings (Mondays, 8:30 AM), and What did I say about your first project.
7. **Icon.** `BrandArt.iconAsk`: a speech bubble holding a short sound wave, on the 24-unit grid (`mac/tools/gen_icons.py`). Native uses `questionmark.bubble`.

## 20. Apple Watch

Apple Watch capture (mockup "Library features", section 4, October 26, 2026) records a voice note or a thought on the watch and sends it to the iPhone, which transcribes it and syncs it to the Mac like any other recording (`VerbatimWatch`, `VerbatimWatchWidgets`, `Model/WatchTransfer.swift`, `Model/WatchImport.swift`, `VerbatimPhone/PhoneWatch.swift`). The watch app needs watchOS 11; the iPhone app still runs on iOS 17.

1. **Always dark.** The page is the app's dark paper, text is paper, and persimmon means record (`WatchInk` in Tokens.swift; ink on the record fill, 4.7:1). Record is the one persimmon fill at rest; New thought is outlined, as on Home (§14.10). While recording, Stop is the fill and Mark is outlined. The big buttons use `Radius.watch`.
2. **Home:** the wordmark top left, Record (an ink disc with the capture glyph in persimmon) and New thought (`iconThought`), then "Today · 6 thoughts" in dim sans, and "2 recordings waiting for your iPhone" while any wait.
3. **Recording:** "● Recording" (or "● New thought"), the time in `Ink.mono(40)`, 13 persimmon voice bars that follow your level (still under Reduce Motion and on the dimmed always-on screen), and Mark and Stop as 58 pt circles with their names under them. Double-tap your fingers to mark on a watch that supports it (`handGestureShortcut(.primaryAction)`). Record plays `.start` just before the microphone opens and Stop plays `.stop` once it has stopped; a start that fails plays `.failure` (§7). A mark plays `.click` and shows "Marked 4:12" (the time in mono) on a paper capsule for two seconds; a second mark within 3 seconds confirms the first, as on the iPhone (§18). Recording keeps going with your wrist down (the audio background mode); it stops and saves when another app takes the microphone or the watch drops under 15 MB free, and it won't start under 50 MB.
4. **Sent to iPhone** as soon as Stop queues it: a ring with a persimmon check, "Your iPhone transcribes it and adds it to the Library." (or today's Thoughts; "gets it when it's in reach" while it's away), and "Voice note · 41:05 · 3 moments" in mono. It returns to Home after six seconds or Done.
5. **Never lose a recording.** The audio (AAC, mono, 22.05 kHz) and its details are written as it records, so a recording the app was closed in the middle of goes out at the next launch. Stop moves it to the outbox and `transferFile` sends it with its `WatchTransfer` (kind, start, length, marks); Watch Connectivity queues it until the iPhone is in reach. The watch deletes the audio only when the transfer finishes without an error, and sends anything left again at launch, when the iPhone comes back, or two minutes after a failure.
6. **On the iPhone.** Watch Connectivity activates before launch finishes, so a file arrives in the background too. It's moved into the Watch inbox, then imported through the same path as a shared file (`importSources`), once per recording ID. A thought is a Thoughts recording you chose (`idea`) on the page of the day it started, its meta line saying "Apple Watch" (`ThoughtText.origin`); a voice note is a voice memo whose kind AutoLabel picks. Marks become moments from the Apple Watch (`MarkSource.watch`: "Moment 11:47 · from the Apple Watch"). An import that fails keeps the audio in the inbox's Kept folder.
7. **Complications and the Smart Stack** (WidgetKit, drawing only, from the App Group): the circular Record (the bars mark in ink on persimmon) opens the watch app recording a voice note; the rectangular "6 thoughts today · Tap to add one" opens it recording a thought; the Smart Stack card shows your last capture ("Thought · 0:42 · 9:58 AM", `privacySensitive()`) and "Tap to record", scored higher for two hours after a capture. Tinted faces draw them in one color. The count comes from the iPhone (`updateApplicationContext`, when the library changes), plus thoughts still waiting on the watch, and drops to none when today's page ends.
8. **Signing.** One switch leaves the watch app out of the iPhone app (`VERBOSE_WATCH=NO bash tools/generate-project.sh`); TestFlight retries without it if the watch app fails to sign (mac/APP_STORE.md, "Apple Watch").
